# ShopKart Call Center Analytics - Data Dictionary & Validation Report

ShopKart is a **fictional** Indian e-commerce marketplace. All data is synthetic, generated by
`shopkart_generate_data.py` (seed 2026). No real company data is used or implied.

## 1. Read this first - what differs from the original handoff

| Item | Handoff | Delivered | Why |
|---|---|---|---|
| Orders | ~75,000 | 100,000 | Keeps the call-to-order ratio believable with 49,580 calls |
| Calls | ~50,000 | 49,580 | Same |
| Agents | ~75 | 22 | 75 agents would be only a few % busy at ~275 calls/day, so nobody would ever wait. 22 agents gives realistic queues at peak. |
| Period | Jan-Jun 2026 | **Calls Jan-Jun 2026; orders and DimDate start 1 Dec 2025** | Warm-up month so January calls have order history. Without it early-January volume looks artificially low. |
| DimDate rows | ~365 | 212 | 1 Dec 2025 - 30 Jun 2026 |
| Call reasons | 20 | 18 | Merged overlapping reasons (Payment Issue + Payment Failure; Order Modification + Delivery Address; two Complaint rows) |
| CallStatus | Answered / Abandoned / Disconnected / Transferred / Voicemail | Answered / Abandoned / Disconnected / Voicemail | Transfer is its own flag (TransferFlag); it is not a status |
| ResolutionStatus | included "Escalated" | Resolved / Partially Resolved / Follow-up Required / Not Applicable | Escalation is its own flag (Escalated) |

**Reporting window:** put a report-level filter on DimDate for **1 Jan - 30 Jun 2026**. December 2025 orders exist only
as order history; calls made in December are not in the extract, so December contact-rate figures are understated.

**Realism caveat (say this in an interview):** about 25% of orders generate at least one call.
Real marketplaces see far lower contact rates. This is a deliberately high-contact simulation so that every
page has enough signal. Call it out as an assumption.

### FactOrders - extra column
- `OrderValueBucket` (not in the handoff): "1. Under 1,000", "2. 1,000-2,499", "3. 2,500-4,999", "4. 5,000-9,999", "5. 10,000+". Numeric prefix makes it sort correctly.
- `DeliveryStatus` has two values beyond the handoff list: **In Transit** and **Not Applicable** (cancelled / still processing orders).
- OrderStatus and DeliveryStatus are the **current status as of 30 Jun 2026**.

### FactCalls - columns
`CallID, CallDate, CallTime, CustomerID, OrderID, AgentID, CallReasonID, CallStatus, WaitSeconds, TalkSeconds, HoldSeconds,
AfterCallWorkSeconds, HandleSeconds, ResolutionStatus, Escalated, TransferFlag, CSAT, FirstContactResolution`
plus these additions:

| Column | Meaning |
|---|---|
| QueueName | Team queue the call reason is routed to (so abandoned calls, which have no agent, can still be reported by queue) |
| ServiceLevelFlag | Yes if the call reached an agent (Answered or Disconnected) within 60s |
| IsRepeatContact | Yes if this call is a follow-up to an earlier call by the same customer on the same issue (max 3 contacts) |
| ProductID, OrderStatus, DeliveryStatus, OrderValueBucket | Order attributes copied onto the call. **This is how Page 2 works without a FactCalls-FactOrders relationship** (avoids an ambiguous Customer -> Orders -> Calls path). Calls with no order show "No Order". |

**Blank (null) values are intentional**
- `OrderID`, `ProductID`: blank for Account/Login, Product Information, Subscription, general Complaint, and some Payment/Seller calls.
- `AgentID`: blank for Abandoned and Voicemail calls (no agent ever took them). Do not delete these rows.
- `CSAT`: blank unless the call was Answered **and** the customer answered the survey. Never treat as zero.
- `FirstContactResolution`: blank unless CallStatus = Answered.

## 3. Business rules used in the data (and the KPI definitions to use)

| KPI | Definition used |
|---|---|
| Total Calls (Offered) | Count of CallID. Includes Voicemail. |
| Answered / reached an agent | CallStatus is Answered **or** Disconnected (Disconnected = connected to an agent, then the call dropped) |
| Answer Rate | Calls that reached an agent / Total Calls |
| Abandonment Rate | Abandoned / Total Calls. Voicemail is **not** counted as abandoned. Short abandons (<5s, about 1.5% of calls) are **included** - mention it, or exclude them for an industry-style variant. |
| Service Level | ServiceLevelFlag = Yes / Total Calls (reached an agent within 60s). Target line: 80%. |
| Average Wait | Show both: all offered calls, and calls that reached an agent. For abandoned calls WaitSeconds is how long the caller waited before hanging up. |
| AHT | TalkSeconds + HoldSeconds + AfterCallWorkSeconds, averaged over Answered calls |
| CSAT | Average of non-blank CSAT |
| FCR % | FirstContactResolution = Yes / Answered calls. Yes requires: Resolved, not escalated, not transferred, and no repeat call followed. |
| Resolution Rate | Resolved / calls whose ResolutionStatus is not "Not Applicable" |
| Escalation Rate | Escalated = Yes / Answered calls |
| Repeat Contact Rate | IsRepeatContact = Yes / Total Calls (or recompute it with DAX as practice) |

Staffing model: 6-hour blocks (Night 00-06, Morning 06-12, Afternoon 12-18, Evening 18-24), 2 days off a week per agent,
about 6% random absence, a 30-minute break per shift. Real centres use 8-9 hour overlapping shifts; blocks keep the model simple.
Agents are routed by team but will take other queues when their own team is busy (cross-skilled, slightly worse outcomes).

## 4. Patterns deliberately built into the data (what your dashboard should find)

1. Delayed and failed-delivery orders generate far more calls per order than on-time ones.
2. Sale events (late Jan, mid Apr, mid Jun) raise order volume and delivery delays, so call spikes follow about a week later.
3. Call volume peaks 18:00-21:00 and 12:00-18:00, and Mondays are the busiest weekday.
4. The evening block (peak 20:00) is the weak spot: waits, abandonment and SLA breaches are worst there, and worse on Mondays and in June. There are smaller SLA dips around 09:00 and 14:00 where staggered breaks thin the coverage. Overall service level lands close to the 80% target, so the story is *where and when* it fails, not that it always fails.
5. Longer waits mean more abandonment and lower CSAT.
6. Refund, Payment, Seller and Complaint calls escalate most, have the longest AHT, and the lowest resolution and CSAT.
7. Orders of 10,000+ escalate more. High Value customers escalate more and rate support slightly lower, despite fewer calls per order.
8. Senior agents have higher FCR / resolution / CSAT and lower AHT; freshers the opposite.
9. **Planted agent stories for Page 4:** AGT002 is fast (low AHT) but weak on resolution and CSAT; AGT009 is slow but excellent. Do not rank on AHT alone.
10. East / remote locations (Guwahati, Srinagar, Dhanbad, Ranchi, Patna) have higher delay rates. Low-rated marketplace sellers cause more delays, wrong-product and seller-issue calls. A few "problem products" generate outsized damage complaints.
